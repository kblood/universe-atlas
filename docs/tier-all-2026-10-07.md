## 3. Estimates

`tests/tier-estimates.json` holds three tables:

- `smoke`: 50 steps from the smoke run above, plus 3 older rows for the O4 files that work falls back to;
- `all`: 246 steps from the test:all run above;
- `full`: 246 steps from the gate run above.

Each table records its sources as `{runId, commit, dirty, wallS}`. The commit shas are those of pre-rebase WIP commits,
so the `runId` (tree key plus start time) is the stable identifier. Before the measured run, `full` was seeded title by
title from GATE-2's per-test durations, then from B's alone-measured O3 numbers. The measured run replaced both.

Refresh the tables after a run that changed the timing picture:

```
npm run tier-estimates -- full test-results/tiers/<treeKey>-full-<start>
npm run tier-estimates -- smoke test-results/tiers/<treeKey>-smoke-<start>
```

A local run of the same label always wins over the table, so the table only matters in a fresh worktree or for a label
that has not been run yet. `tier-all.test.mjs` asserts that the table covers at least 95 % of the registry's `all`
steps.
