## What the diagnosis found (measured, unofficial)

With the mountains wired the coarse tile build is +18..+33% per level against main although the genuine mountain work
is +2..+5%. Three separate causes, each measured:

1. Building the M1 layout (continentalA0 calls catalog.ts `noise`/`macroHeightCode`) slows every later plain sample
   by ~+13%. Private copies of those kernels inside continentalA0 (bit-for-bit) remove it.
2. Running the exact M1 path (`massifBeltSample` -> `sampleWithinWithA0`) with the CALLER'S direction array `d`
   slows every later plain sample in the process by +15..+60%, even in a different core function. Passing a
   core-owned scratch copy of d (`scr[0]=d[0]; scr[1]=d[1]; scr[2]=d[2]`) instead removes it (V8 effect; the copy is
   value-preserving). It only works if the exact path lives in a SEPARATE core function literal from the coarse path
   (one function with both branches: still +16%).
3. Even then, the exact M1+M2 path at coarse levels costs +12%: coarse levels must not run M1 per sample. A baked
   per-body table read by coarse levels (prototype) brought coarse tiles to main +-3% when causes 1 and 2 were also
   fixed.

    massifBlendWeight define them. Return main unchanged (the same value, Object.is) when w_lo === 0 and U_hi === 0.
