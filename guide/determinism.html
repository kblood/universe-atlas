01 / Identity & reproducibility

The same place. The same time.

A seed is the starting point. Reproducibility also needs the complete address, exact date and the versions of the algorithms that interpret them.

Randomness with a stable address

catalog.ts hashes text with a 64-bit FNV-1a hash and uses PCG32 streams for seeded choices. Generation keys are derived from an entity’s identity, so generating a neighbouring system does not consume a shared global random sequence and change the next planet.

The same inputs resolve the same catalogue records without storing every star or patch of ground. Human-readable names can repeat. Canonical identifiers distinguish objects even when names or local labels match.

seed → identity key → seeded choices → generated record

Determinism also applies to history: a lifecycle is created once from identity, then queried at a date. Directly seeking to that date and visiting it after other dates should produce the same state.

The complete location

address.ts defines cluster, group, galaxy, system and body addresses. A body identity extends its parent hierarchy with a body slot. A local surface position adds a body-fixed direction or offset; it does not become a new planet.

LayerRepresentation
ClusterSigned BigInt cells, each 100 Mpc across.
Group5 Mpc cells; each coordinate is a local offset from 0 to 19 within its cluster.
GalaxyAn ordinal within its addressed group.
SystemGeneration cell and system ordinal; sector coordinates are derived from that cell.
Body & local positionA planet, star or moon slot, plus an explicit coordinate frame and local offset.

Euclidean division keeps negative cell coordinates consistent. The legacy root spelling, such as G001/C2128,0,1/0, remains parseable. A local G001 alone is not globally unique across generated groups.

The address model extends beyond the root group. The current interactive scene still navigates the root 32-galaxy catalogue; broader address support does not yet provide a UI for travelling through all generated groups.

Exact dates, bounded animation phases

The clock stores signed BigInt nanoseconds since the Big Bang. The navigable baseline interval is closed at both ends: 0 through 10100 years. Dates serialize as decimal strings, avoiding floating-point loss in saves and URLs.

Orbits, spin and animal animation reduce time to a bounded remainder before converting to floating-point phases. This allows a date far beyond ordinary JavaScript numerical precision to retain useful local motion. The timeline’s slider is a navigation convenience; exact decimal entry and serialized dates have a different precision contract.

Bookmarks carry the model

time-nav.ts writes date, wv, mv and bv: the date, world-version bundle, combined model identity and client build identity. The bundle includes time, space, cosmology, catalogue, history, surface, terrain, biosphere and galaxy history.

Legacy dates without the current time convention are interpreted relative to the catalogue epoch. New bookmarks use absolute time. Compatibility messages identify older or unrecognized models, because an algorithm change can alter the world behind an otherwise valid address.

A version warning is not an old-engine replay. The current application reports compatibility differences. It does not ship every historical generator or automatically reproduce an older build’s scenery.

Determinism has explicit boundaries

det-math.ts supplies fixed arithmetic approximations for decisions that affect identity, thresholds or discrete generation. This avoids depending on small browser differences in transcendental math. Ordinary continuous animation can still use floating-point evaluation with tolerances.

Canonical hydrology is generated from a fixed candidate set. Selecting a river changes which region receives rich visuals; it must not create a new river or alter physical existence. Local animal anchors and dated poses likewise resolve without replaying previous frames.

The repository includes reference-vector, visit-order, direct-seek, existence-gating and compatibility tests. Its golden harness compares Node, Chromium, Firefox and WebKit. Those are verification tools, not a promise that every untested change or every GPU renders identical pixels. Level of detail, scheduling, shaders and hardware can change appearance while catalogue identity remains stable.
