### Diagnosis (read-only, not fixed)

- The test spawns a child `node --test` with `--test-reporter=tests/helpers/tier-reporter.mjs` and
  `env: {...process.env, NODE_TEST_CONTEXT: undefined, ATLAS_TIER_RESULTS: out, ATLAS_TEST_TIER: 'smoke', ATLAS_TIER_AWARE: '1'}`.
  It does **not** clear `ATLAS_TEST_FULL`.
- `npm run test:full` sets `ATLAS_TEST_FULL=1` for the whole run (`tests/helpers/test-runner.mjs:25`), so the child inherits it.
- `tests/helpers/tier-reporter.mjs:21` gives `ATLAS_TEST_FULL === '1'` precedence over `ATLAS_TEST_TIER`, so the tier becomes
  `gate` and the coverage is `full` (line 42), not the `subset` the test expects for `smoke`.
- The neighbouring probe in the same file (line 40) already clears it (`ATLAS_TEST_TIER: '', ATLAS_TEST_FULL: '', ...env`);
  the reporter test lacks the same clearing. The test arrived with the tiered-tests MVP (`e7006e8`, merged in `27ce1bf`),
  whose verification covered smoke/default but not test:full.
- Reproduced deterministically in isolation:
  `node --test --test-name-pattern="reporter: one complete" tests/tier.test.mjs` passes with `ATLAS_TEST_FULL=''` and
  fails with the same assertion with `ATLAS_TEST_FULL=1`.
- Classification: a real test bug (environment leak in the test), not load-sensitive and not a product/terrain regression.
  The tier reporter's precedence rule itself matches its documented contract (`tests/helpers/tier.mjs:3-4`: `ATLAS_TEST_FULL=1` implies `gate`).
- Likely fix (for the L1 test-infra owner, not applied here): add `ATLAS_TEST_FULL: ''` (or `delete`) to that child env in
  `tests/tier.test.mjs`, as the line-40 probe does. Then re-run GATE-2 → GATE-3 → GATE-4 on the fixed sha. Allowlisting it in
  `known-failures.json` would be the wrong remedy (it is a HARD test that is simply wrong under test:full).
